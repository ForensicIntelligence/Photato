# Write layer styles by tile and reuse opacity checks

Advanced layer effects write their final pixels by tile. Ordinary raster writes also reuse an opacity result owned by a single surface. An edited surface detaches the proof when another snapshot shares it. The compositor uses the same sample conversions as scalar writes and invalidates the proof once the batch finishes. The requested region and the existing tile padding rules still bound the writes.

Both tested wide oblique Pattern Overlay fits and the separate native Fit and soft-proof PNGs match build 693 byte for byte. The RGB8, RGB16 and RGB32 layer-style regression probe matched the previous build for all 138 cases in both direct rendering and imported-project rendering. The mapped-raster tests check that an edited copy and its original can certify opacity independently, and that tile writes reproduce scalar storage in each tested sample encoding and depth.

On optimized Apple Silicon, fitting the 4,161 × 4,101 source with a 512 × 512 tile took 5.30 s in build 693 and 3.29 s in build 694. The 5 × 5 tile took 5.24 s and 3.24 s. Each output contains 1,430,352 Float32 RGBA bytes. Writing 2,097,152 samples into a copy of an opaque surface took a median 168.3 ms in build 693 and 41.5 ms in build 694. The written bytes matched on both architectures.

The optimized Apple Silicon Brush preview matched command output for all three tested RGB8 canvas sizes. For the 6,000 × 4,000 case, p95 time from an EditorStore input to its published snapshot was 1.80 ms in build 693 and 1.73 ms in build 694. This software measurement excludes physical input delivery and display presentation.
