# Document guides — checkpoint 330

Status: guide workflow tested at330 Source07. All297 affected cases and18 new cases pass. Three original projects retain30 Float32 guide words, and the independent reader verifies8 saved files/80 guide records. These are scoped checks; full Photoshop parity remains unfinished.

Document guides are nonprinting lines in document pixel coordinates, separate from artboard-local guides. Native guide records have stable IDs, orientation, position and color. They save in native archive78 and participate in history. View visibility, locking and snapping are editor state. New Guide accepts px, %, in, cm, mm, pt and pc; current ruler labels and New Guide Layout distances use pixels.

Use the existing View > Guides menu for New Guide, Edit Selected Guides, New Guide Layout, locking and clearing. Layout supplies columns, rows, gutters, margins, color, preview and Clear Existing Guides. Preview and Cancel leave the document unchanged; a stale dialog refuses to commit. New Guides From Shape uses the active layer bounds. Clear Canvas Guides affects document guides; Clear Guides also clears artboard-local guides.

Dragging from a ruler creates a guide. The Move tool selects and moves existing guides. Shift+Option-click selects multiple guides; Option during a drag changes orientation, and Shift snaps to the current pixel ruler ticks. Dragging a guide into the ruler or outside the viewport removes it. Escape, tool changes and focus loss cancel a pending drag. The shared cursor policy shows the guide's effective axis and Shift constraint. Lock Guides prevents editing. Move-tool layer bounds/centers snap within eight view points when Snap and Snap To Guides are enabled; Command suppresses that snap on macOS. The existing integer layer-position precision remains a limitation for fractional guide targets.

Whole-document image/canvas size, crop and orthogonal turns/flips map guide coordinates. General oblique geometry cannot represent tilted guides and explicitly rejects rather than dropping them. Original PhotoCraft imports retain Float32 guide positions exactly, including signed zero. PSD/PSB resource1032 stores signed1/32-pixel positions: unchanged records retain their original bytes/order and grid header words; editing regenerates the record with disclosed quantization. Colors persist natively. PSD/PSB saves with custom colors explicitly reject until modern Photoshop colored-guide records are implemented; the Save dialog and API report the same limitation. Earlier native files with only an opaque resource1032 promote those guides at shared desktop/API admission before a typed guide edit can add or clear lines. The source resource remains retained.

The optional API adds guides.edit (add, replace, update, delete, clear, clearAll and layout) and guides.view (visible, locked, snap and enabled). State includes guide records, selected IDs, view options and edit availability. Both use the desktop engine and document history. Native transfers require version78 for typed guide documents. Existing Adobe-compatible file/job operations share the serializer within their own limits. No Adobe guide endpoint or descriptor is invented. Semantic guide Actions remain explicitly unsupported.

The reference harness uses unchanged original Rust crates and owned artwork. Three source projects provide30 Float32 guide words; expected resource1032 bytes follow the original writer's formula. Two separately assembled public-format PSD/PSB inputs cover independent file framing. These are not live Photoshop2026 acceptance files. Current primary Adobe guide help and the public file-format specification supply control/format references. Photoshop access still reports a locked Mac; a manual-unlock request is pending.
