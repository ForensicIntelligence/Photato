# Large native channel arithmetic

Build 396 extends the existing Apply Image and Calculations workflows to logical native-component documents up to 300,000 pixels per side. The affected tests pass on Apple Silicon and translated Intel:103cases per architecture, including 13 new cases. See [qualification](LARGE_CHANNEL_ARITHMETIC_396.json).

Apply Image retains the small-document loop. Large native layers use numeric source, mask, selection and opacity projections, then build one component plane at a time. Intermediate weights remain Float32. Unselected planes, profiles and alpha protection retain their separate roles; CMYK density is inverted only for channel arithmetic. Integer storage expansion uses exact raw reframing instead of scanning the logical canvas. The sampled sparse expansion fell from 88.182/88.622 seconds to 0.013/0.019 seconds in the two architecture runs. These are individual test observations, not a 60 fps or dense-capacity benchmark.

Calculations can create a large grayscale document from its numeric output without initializing every implicit pixel. Source documents and their Undo history stay unchanged. The existing New Channel and Selection results still commit one native Undo. New-document API output requires enabled document transfers. Native86retains the large component planes; dense legacy exports and printing plates have separate limits.

The native sheets and optional API share preparation and transaction code. Existing `image.applyImage` and `image.calculations` schemas are unchanged; capabilities report the logical maximum and remaining constraints. Tests cover draft preview/cancel/commit, Undo/redo, source leases, invalid/busy/stale requests, transfer 403/201 and native86download/reopen. No new Adobe route or unqualified action descriptor is invented.

The dense-versus-bounded tests compare every raw plane word across supported component modes/depths and all21 existing blends. Independent Python checks verify 72 emitted bytes per architecture against literal grayscale/opacity words. These establish the tested arithmetic and storage behavior, not Photoshop pixel equivalence. Adobe documents [Calculations result choices](https://helpx.adobe.com/photoshop/desktop/adjust-color/hdr-and-channel-manipulation/blend-channels-using-calculations.html) and [Apply Image options](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/objects/options/applyimageoptions); those references do not specify complete numerical kernels.

Current live UI remains unqualified because the Mac is locked. Full S05/C01, independent channel visibility, profile/custom-gray/default fidelity, semantic Actions/Adobe descriptors, large interchange, full current-suite success, physical supported Macs/macOS14+, dense capacity and sustained 60 fps remain open. The earlier Gray32 one-ULP difference and historical missing binaries are retained in the record.
