# Component archive streaming

Checkpoint390 adds a raw component codec to native file version86 and ephemeral history. The native application still admits at most8,388,608 component pixels. The ComponentPlane storage module supports sparse300,000×300,000 geometry; that module limit is not an application-capacity claim.

A plane record contains format version1, dimensions, depth, an implicit raw word, stored block count, optional root reference and root level. Each sample block contains4096 little-endian samples: unsigned8, unsigned16 or finite Float32 words. Hidden colour, signed zero, subnormals and HDR colour values retain their exact bits. Float32 alpha must lie in0…1. Padding outside the logical plane must match the implicit word.

A binary page starts with ASCII PHTCMP01, level and reserved bytes, then a little-endian UInt16 entry count. Each entry has UInt32 lower/upper block keys, UInt32 subtree block count, a one-byte reference length and an ASCII alphanumeric owned-blob identifier. Leaves hold at most1024 entries and branches256. The maximum level is2. Every page has an exact bounded length. Levels decrease during traversal; ranges must be ordered and disjoint, subtree counts/ranges must match, and the final exact count must equal the record. References identify authenticated archive/history blobs, never external paths. Component payloads bypass the RGBA tile decoder.

Encoding visits ordered retained blocks using bounded partial pages. Decoding publishes a private immutable unlinked mapping only after all checks and synchronization succeed. Failure or cancellation discards the candidate. Presence-map and transfer-buffer admission is separate from logical sample size and OS-managed mapping residency. Paged native reads share their scratch allowance across RGBA tiles and raw components; ordinary owned reads retain conservative logical component heap admission. History keeps its existing owned blob index and quota, so the codec alone does not establish bounded whole-document history metadata at maximum dense capacity.

Native versions1–85 retain their previous read layouts. Explicit older Data/API exports keep their existing whole-plane representation and admission. Explicit version86 selects component pages; ordinary native file save selects86 when a top-level layer retains native components. Nested component content also uses pages when the container is86; selecting86 automatically for every nested feature remains a separate save-policy task. Actions remain version46. No tool, shortcut, cursor or new command is added.

Existing native API downloads accept X-Photato-Archive-Version:86 and publish read-version/format/storage metadata. Imports use the same checked native decoder and transaction path. Stale revisions, revoked transfers and upload/download limits retain their existing behavior. There is no new Adobe endpoint; applicable existing resource/job codecs continue to share the native engine within their pinned contract and budgets.

Full-capacity admission still needs creation/conversion/cache policies, dense and default-changing edits, resampling/reframe/trim, history/recovery metadata, printing and PSD/PSB/TIFF streaming. Full current-suite success, exact Photoshop output/settings/shortcuts, supported physical Macs and sustained60fps remain separate requirements. The current qualification record is docs/COMPONENT_STREAMING_390.json when completed; ongoing attempts are recorded in DEVLOG step390.
