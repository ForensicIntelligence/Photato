# Large-document Crop

Crop uses the document engine's300000pixel side and90gigapixel logical extent for RGB. The old16MP source/output and64MP aggregate raster-delete guards are removed. This is working-source admission, not a claim that every dense maximum-size job has been qualified.

Small mapped extracts retain the previous intersecting-tile loop to avoid extra cache/scratch work; mapped extracts above131072pixels and large outputs page their raw copies. Integer delete crops page exact stored samples, including implicit/default, hidden-alpha and HDR values. Retained crops keep source pixels. Rotated deletion clips its projected bounds to the output before sampling bounded2048×64patches with the existing crop kernel. Masks keep their world placement; saved channels follow the crop, with exact integer sampling. Paths and guides retain the existing canvas mapping. Undo and stale-source checks remain shared.

Background Color expansion streams generated edge patches without a canvas-sized Boolean array. Existing interior transparency remains. Deleting Background crops reframe the opaque canvas using the captured background color. Sole-Background Content-Aware expansion samples the unfilled outside region. The current Adobe guide requires conversion before retaining pixels in a sole-Background image; Photato requires explicit conversion for all Background retention requests and for layered Background Content-Aware expansion. That broader context remains open. State exposes canRetainCroppedPixels and native controls reflect the available target. Native previews project into images no larger than1024pixels per side; working/source/export pixels are not reduced. A large preview still requires the native composition pipeline and can be expensive for complex content. Cancellation remains available. Content-Aware exposed output retains its separate4MP synthesis budget; no-fill/enclosed requests do not allocate that synthesis input. Native-component, Indexed/Bitmap and ink processing retain separate limits.
