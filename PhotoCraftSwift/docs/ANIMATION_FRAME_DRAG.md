# Reorder animation frames

In the frame Timeline, drag a thumbnail to the left or right half of another thumbnail. An insertion line marks the proposed position. Dropping moves the frame before or after that target through the existing reorder command. The arrows remain available.

Dragging selects its source frame without adding content history. A changed order adds one Undo entry and retains frame IDs, delays, layer states, shared content and selected-frame appearance. The native archive format is unchanged. This increment supports one frame at a time; modifier keys do not duplicate frames or enable a multi-frame action. Physical drag feedback, auto-scroll and exact Photoshop modifier behavior remain unqualified.

The transfer contains a private process-local token, without image or frame contents. It captures document, session, panel lifetime and weak document ownership. Source edits, selection changes, panel hiding, document detachment, playback, another drag, cancellation and malformed or foreign transfers invalidate it. Dropping at an unchanged position adds no history.

The Photato API uses the existing `animation.view` operation to select the source `frameID`, then `animation.edit` with `operation: reorder` and the final zero-based `index`. `animation.nativeFrameDrag` capability metadata explains native insertion edges and the shared operation. Selection does not add content history; reordering does. There is no dedicated frame-animation endpoint in the pinned Adobe contract, so no Adobe route or descriptor is added. Portable animation Action recording remains unavailable.
