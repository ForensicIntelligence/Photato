# Drag and copy Smart Filters

Checkpoint414 adds single-filter dragging in the Layers panel. Drag onto another filter row to reorder within the same stack. Hold Option when dropping to copy a filter within the same document, including onto another Smart Object. A filter-row destination uses that stored array position; a layer row or Smart Filters header appends at the visual top. The panel displays application order in reverse: stored index0 runs first.

A copy gets a fresh filter UUID and retains its complete settings, enabled state, opacity and blend mode. Source Smart Object bytes stay unchanged. Existing target stack enable state, mask and mask properties are retained. A new stack uses the existing selection-mask policy. One native prepared transaction handles renderer validation, history, persistence and portable resolved filter-stack Actions. Undo restores the document. Busy/locked/over-budget/stale/closed/foreign/superseded/malformed/no-op transfers cannot commit.

The private own-process provider carries a random token, not document contents. Its registry holds weak store/controller references and generation/ID checks. Drop feedback and the dispatched action share the live Option resolver; the action is captured at drop before asynchronous data loading. Native layer-string drag/drop retains its separate type. Actual physical hit testing, system feedback and modifier timing remain unqualified while the Mac unlock request is pending.

The optional API already supports the resulting edit through `smartFilter.set`. Read the target stack, supply its complete ordered `filters` array with the copied item assigned a fresh unique UUID, retain target `enabled` and use existing mask keep/settings. State-only `hasMask` and `maskTransform` fields are not request fields. `capabilities.smartFilters.nativeDrag` documents the mapping. No operation, request parameter, Adobe route/descriptor or native/Actions format is added; catalog245/native86/Actions47 remain.
