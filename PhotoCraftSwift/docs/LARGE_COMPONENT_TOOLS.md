# Large component tools

Checkpoint393 tests the paths below on Apple Silicon and translated Intel. All12new cases pass; remaining affected failures reproduce on preserved392. Full current-suite, live UI, physical maximum capacity and Photoshop comparisons remain open. See [the qualification record](LARGE_COMPONENT_TOOLS_393.json).

Individual Gray, CMYK, Lab and retained RGB channel edits use numerical component values. Fill, Invert, Brush/Eraser and the eight supported basic filters now have a large-plane path through the same `ModeComponentEdit` transaction as the desktop and API. The previous small-document path remains as a regression reference. CMYK tools still edit view-gray, where black means full ink; numerical channel read/write still uses stored ink values.

The large path reads bounded numerical projections and writes immutable component blocks. Fill and Invert combine exact byte/255 selection coverage with their existing arithmetic. Coverage uses the original forward transform and floor operation, including moved, scaled and rotated layers. Uniform coverage remains implicit. Eligible sparse masks project a bounded support list; other cases evaluate bounded patches. Untargeted native components and alpha remain shared.

Brush and Eraser use the existing scalar brush engines and selection/transform routing. Filters use the existing eight basic raster engines on a numerical proxy. Float32 channel samples are reinterpreted as linear numeric values for filtering, without an RGB transfer. The result returns to numerical channel storage. Uniform binary Motion Blur uses an exact constant shortcut; fractional constants retain the prior interpolation and accumulation loop. The RGB-only cache bridge preserves its previous encoding semantics, with full Photoshop and bit-level colour qualification still separate.

These paths remove the eight-megapixel component-tool admission limit. They do not make every dense operation fast or fit every job on every disk. Brush coverage, filter scratch, component and raster-store limits, cancellation and real I/O remain authoritative. A nonuniform maximum-size filter or dense selection can require substantial disk space and time. Candidates publish only after completion; failed or cancelled prepared edits retain the source and history.

Existing menus, selected targets, factory shortcuts and API commands are retained. `mode.channel.edit` capability metadata reports the logical limit, eight filters, storage policy and remaining restrictions; availability now matches the shared implementation. No new tool, modifier action, Adobe route or unsupported descriptor is introduced. Native86 is still required for large component persistence. Adobe-compatible coverage remains separately qualified.

The full target remains Photoshop 2026 equivalence, including all remaining channel, visibility, arithmetic, profile, interchange, printing, metadata/recovery, history and editing contexts. Current live UI, exact output/default/settings/shortcuts, the full current suite, supported physical Macs/macOS14+, dense maximum capacity and sustained60fps remain open. The prior Gray32 cross-architecture difference and strict failures are retained. S05 is open; full C01 follows its completion and testing.
