# Native component blocks

Checkpoint 388 moves NativeModeRaster onto the raw component storage introduced in checkpoint 387. RGB, Grayscale, CMYK and Lab retain their supported depths, profiles, intent, quantization and alpha rules. Untargeted components retain their raw bytes, including finite Float32 HDR, subnormal and signed-zero values.

Uniform components no longer allocate a whole Data plane. Sparse conversion evaluates the implicit sample and retained Surface tiles through the existing ColorSync implementation. Retained-mode conversion/display merges at most five ordered sample-block streams. Numeric channel replacement, exact cropping and local cache reconciliation share untouched blocks. Reframe uses an implicit background and bounded raw row transfers. Linear cache defaults are compared in their actual stored coordinates; display encoding cannot hide a small linear change. Default-equivalent samples do not allocate derived Surface tiles merely because another sample shares a numeric block.

The public legacy plane exports, native format 85 and Actions 46 remain compatible. Encoding still materializes bounded legacy planes; application admission remains **8,388,608 pixels**. Dense resampling, default-changing reconciliation, printing conversion and component file codecs still need further integration for complete large-document support. The raw plane's larger geometry target does not lift these application limits.

TIFF emits individual raw words in the requested byte order instead of exporting complete planes inside its pixel loop. Ink conversion requests one plane and checks logical alpha, ignoring padding. Existing desktop/API/history implementations stay shared. The mode capability's `storage` metadata describes the sample blocks, implicit fills, raw bits and unchanged maximum. Parameter/result schemas and commands are unchanged. No Adobe endpoint, action descriptor, tool modifier or cursor change is added.

Tests compare numeric bytes, native/API workflows and existing PSD/PSB/TIFF behavior. Independent Python packing checks owned sample outputs. These checks do not prove Photoshop colorimetric/rendering/default equivalence, maximum dense capacity, sustained 60 fps or supported physical platform coverage.

Logical Surface equality now compares sample bits in image bounds across implicit, owned and mapped layouts. Hidden RGB and signed zero participate; tile padding and cache/proof bookkeeping do not. Shared persistent paths avoid rescanning unchanged regions. Differing defaults may be ignored only where the union of actual allocated tiles covers every document pixel. This prevents storage representation from breaking native round trips, Undo or API source comparisons. These equality changes require broader Core qualification, with unresolved cases retained independently of focused module passes.
