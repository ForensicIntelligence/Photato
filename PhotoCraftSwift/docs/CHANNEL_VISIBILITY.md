# Channel eyes and editing targets

**Build398:** Temporary pixel-layer and Smart Filter-mask rows stay available with RGB selected. Their eyes retain the editing target; their names select the existing mask target while retaining its display. Vector masks remain in Paths. All404targeted cases pass on each architecture, including16new cases; packaged native mask painting, Undo, RGB/backslash and Filter-Mask-only rows were checked. [Evidence](TEMPORARY_MASK_CHANNELS_398.json).

Build 397 separates saved alpha/spot visibility from the selected editing channel. Several saved masks can remain visible while the image, a component or another saved mask receives edits. Quick Mask keeps its own temporary eye. The eye changes the display; selecting a row changes the editing target. Selecting RGB or an image component hides saved alpha/spot eyes, matching the observed Photoshop 2026 workflow. To edit the image with masks over it, select the image target first, then show the saved masks with their eyes.

Click an eye or drag through the eye column to apply the starting eye’s visible/hidden state to each visited row. Dragging outside the eye column does not toggle names. Escape, focus loss and window loss cancel a native sweep and restore its captured view if the document is still the same. Eye controls expose accessible visibility values and keep the standard control cursor. All 16 Control/Command/Option/Shift combinations retain the same ordinary eye action; alternative Photoshop eye gestures remain unimplemented.

Visibility belongs to the open document session. It does not change pixels, document dirty state, Undo or saved files. Deleting a channel removes it from display, while retaining enough view memory for Undo to restore it. Removing the final auxiliary row restores image display. Reopen/revert and document/mode replacement reset this view. Build397 keeps isolated layer-mask viewing separate. The398 implementation converts a legacy isolated view to independent eyes when an eye actually changes; a native sweep can cancel back to the captured isolated view.

Canvas and channel-preview.png use the same ordered presentation. Saved masks follow document order; Quick Mask follows them. One auxiliary channel alone is grayscale. Several auxiliary channels without the image use overlays over white. All-hidden viewing with auxiliary rows is transparent; documents without auxiliary rows retain their last visible process channel. Numeric reduction is bounded by the viewport, including a tested sparse 300,000 × 300,000 CMYK document. This establishes logical sparse behavior, not physical dense capacity or sustained 60 fps.

The optional Photato API extends existing operations. channel.view with target RGB, a saved channel UUID, or quickMask and visible:true|false changes only the eye. Omitting visible keeps the existing row/target selection action. view.channelVisibility, mode.channel.visibility and ink.channel.visibility retain process-channel behavior with the documented auxiliary-row exception for hiding all image components. auxiliaryVisibility reports imageVisible, visibleAlphaIDs, orderedTargets, quickMaskVisible, grayscale and sweepActive. State schemas and capabilities describe these fields. A no-op does not stale clients; real view changes invalidate the revision. Invalid/busy/stale requests retain 400/422/409 handling. The ordinary preview.png and exports remain independent of visibility. No Adobe route or unqualified channel action descriptor is introduced.

Related neutral component Fill now combines a colour’s alpha with explicit desktop opacity through the existing native primitive. Generic layer.fill and semantic action/job paths use the same neutral partial-opacity behavior; nonneutral colour conversion stays unavailable.

The targeted native/API tests cover editing-target retention, channel combinations, all component modes/depths, spot density, printing contexts, lifecycle, native archive equality, painting/Undo, busy/stale handling, native eye controls and cursor/modifier behavior. Independent Python checks compare four actual 2×2 RGBA outputs with literal expected bytes. Fresh normal-interface Photoshop observations cover saved-eye independence and image-row reset. See [build evidence](CHANNEL_VISIBILITY_397.json) for counts, failed attempts and limits. [Adobe’s channel documentation](https://helpx.adobe.com/photoshop/desktop/adjust-color/hdr-and-channel-manipulation/manage-channels-in-the-channels-panel.html) documents visibility combinations and eye dragging; it does not specify all numerical compositing details.

Full S05/C01 and complete Photoshop parity remain open. Qualification of temporary mask rows, multi-edit selection, alternate eye gestures, hidden-target policy, exact defaults/ICC/output, full interoperability, current full-suite execution, supported physical systems, dense capacity and sustained 60 fps need further work.


The398 API extends `channel.view` for `layerMask` and `smartFilterMask` with `layerID` and optional boolean `visible`. With `visible`, the owner must already be active and only its eye changes. Without it, the existing native mask target is selected and its current display is retained. Missing owners return404, unavailable/inactive mask eyes422, malformed parameters400 and busy/stale requests409. `overlay` is not accepted for these targets. `auxiliaryVisibility.temporaryMaskChannels` describes each available mask’s kind, owner, visibility and selection. Ordered preview targets place the layer mask and Filter Mask before saved alpha/spot planes, with Quick Mask last. Creation-dependent Photoshop ordering/naming is not fully qualified.

Unmodified backslash toggles the available layer-mask overlay without redirecting image edits. The native document window routes it only while the window/canvas has focus, so text fields retain their ordinary keyboard input. Modified backslash actions are not added in this increment. Exact Smart Filter-only/selected-mask shortcut variants and other factory mask gestures remain open. No new canvas tool or cursor action is introduced; these rows use the existing standard-arrow eye controls.
