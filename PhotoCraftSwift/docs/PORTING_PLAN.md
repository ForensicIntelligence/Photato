## Findings and success criteria

**Final product goal: replicate Photoshop functionality in a 100% native macOS application.** PhotoCraft parity is an intermediate migration milestone, not the final scope. Implement the application UI, document model and editing engine in Swift using AppKit, SwiftUI and native Apple graphics/imaging frameworks, with native GPU kernels where needed. Do not ship a Rust backend, Python service, browser UI or JavaScript runtime as a substitute for the native implementation. Core editing must run on macOS 14+; optional Apple Intelligence remains independently gated, including the explicitly authorized Private Cloud Compute integration through Apple's native framework.

The updated user acceptance requirement is exact operation results (byte-identical samples at the applicable depth), the same Photoshop keyboard shortcuts and preferences except intentionally unique features, and familiar workflows on a universal macOS 14+ app. Tolerance-based regressions remain useful during implementation but do not satisfy exactness. Keep separate exactness, behavior, shortcut, preference and platform qualification results.

Completion requires verified editing behavior, professional workflows, editable file interchange, undo/recovery, performance and native interactions across the supported platform matrix. A matching interface, disabled feature entry or passing subset of tests does not complete a Photoshop capability. Track every discovered delta through implementation and acceptance evidence; do not stop at PhotoCraft's feature ceiling.

Upstream is substantial, but **not a complete Photoshop implementation**. Its roadmap explicitly reports incomplete tools, workflows, PSD rendering, performance, and no generative AI. Its scorecard lists 626 wired menu items; wiring is not functional parity. The 24 crate directories contain 257,925 lines including tests. `SOURCE_INVENTORY.json` records exact counts and source hashes; `COMMAND_PARITY.csv` lists upstream menu commands. ## Architecture
