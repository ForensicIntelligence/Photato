# Reuse prepared pattern samples across render patches

Pattern Fill layers and Pattern Overlays share prepared source texels across patches of the same composition. A compositor owns the prepared source and limits retained pattern preparation to 32 MiB. Layers with different placements share source texels. Eligible RGB8 legacy grids share only reductions with the same source and factor. Bilinear sampling wraps each axis once and preserves the four additions and zero-weight handling. [Photoshop layer style options](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/apply-layer-effects/layer-style-effects-and-options-overview.html)

The 5 × 5 and 512 × 512 oblique sources matched build 692 byte for byte in both optimized architectures. Native Fit and soft proof for the separate 70,000 × 520 reference document produced the same PNGs as build 692. Tests covered negative wrap, transparent texels, linked origins, RGB8 reduced grids, source replacement and the cache budget.

On optimized Apple Silicon, the 4,161 × 4,101 source region with a 512 × 512 tile took 6.01 s in build 692 and 5.36 s in build 693. The 5 × 5 tile took 5.58 s and 5.33 s. The output was 301 × 297 with 1,430,352 Float32 RGBA bytes per case. The isolated three-million-sample probe took 68.9 ms and 37.2 ms respectively on Apple Silicon. A separate stack sample showed frequent opacity-proof allocations in the style compositor’s final pixel writes.

460 of 463 selected tests passed in Apple Silicon Debug, optimized Apple Silicon and optimized Intel under Rosetta. The same three failures reproduced build 692's assertions. Four additional storage tests passed in Debug. Both signed macOS 14+ preview slices launched offscreen. Xcode built the corrected project directly in arm64 Debug with signing disabled, then the built app opened a workspace offscreen. Wide nonperiodic fit still evaluates each source pixel.
