#492 — Reviewed edit plans

Recorded 8 November 2026 UTC; selected engine/API checks pass. Native UI and actual model checks remain open.

The existing Actions renderer already applies several edits as one transaction. This change uses that renderer to prepare an edit plan before changing a document. The Apple Intelligence sheet has an Edit Plan workflow with an instruction field, explicit On-device/Private Cloud Compute selection, a list of proposed operations, Before/After images and Apply. Supplied JSON plans use the same review path without invoking or claiming a model. The first declared operations are Auto Tone, Auto Contrast, Auto Color, Desaturate and Invert; the complete assistant/editor requirements remain open.

Native guided generation uses public Foundation Models APIs. On-device planning requires eligibleAppleSilicon/macOS26+; Private Cloud Compute text planning uses the separate27+model. The instruction is the only user content sent to a language model. Image pixels, file paths, layer names, clipboard access and executable tools are not supplied. Runtime model availability is reported honestly. No actual model output has been qualified; injected suggestions are controlled tests.

The optional API exposes strict plan preparation, state, revision-bound PNG previews, application and cancellation. It shares the desktop's prepared native transaction. Unknown operations, arbitrary targets/provider labels/code, oversized or empty plans reject. Native API permissions, bearer/share identity, source/session/lifecycle, stale edits, edit-then-Undo, cancellation and repeated application are guarded. The saved result uses existing document formats and one Undo/Redo transaction. No Firefly endpoint is invented.
