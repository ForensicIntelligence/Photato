## 2026-11-18 — Page large Paint Bucket and Magic Wand regions

The two tools shared a matcher that allocated an RGBA8 sample array and two full coverage buffers. At 300,000 pixels per side those arrays could require about 503 GiB before writing a pixel. This step preserves the existing match rules while replacing those arrays for large documents. The documented controls are tolerance, point or average sampling for Wand, connected and disconnected matching, antialiasing, and sampling visible layers. [Adobe Magic Wand](https://helpx.adobe.com/ie/photoshop/desktop/make-selections/automatic-color-based-selections/select-areas-by-color-with-the-magic-wand-tool.html) · [Adobe Paint Bucket](https://helpx.adobe.com/photoshop/desktop/apply-painting-techniques/fill-objects-selections-layers/fill-paint-bucket-tool.html).

ColorRegion.swift shares the sample average, tolerance test and edge arithmetic. ColorRegionPaged.swift reads transformed source samples on demand and processes bounded patches with a one-pixel halo. Constant, empty and full-coverage results use the implicit GRAY8 sample. When the implicit source and exterior agree, an integer-translated sparse noncontiguous scan visits projected stored tiles and their halo. Contiguous matching retains four-neighbor connectivity and uses a bit per visited pixel, with a small fixed cache and a spillable run worklist.

ColorRegionScratch.swift uses checked file reads and writes. The scratch descriptor is private and the file is unlinked as soon as it is opened. Eviction flushes dirty pages. Cancellation or I/O failure prevents the prepared operation from publishing. PagedSelectionCoverage accepts the already-quantized completed tiles. BucketFill.swift can replace the implicit sample when a full opaque Normal foreground fill covers a canvas-aligned raster. Other bucket modes use the existing writeback. Magic Wand's existing selection.wand endpoint reports the updated storage behavior and still uses the native command.

The new tests compare dense and paged coverage over integral and fractional transforms, masks, depths, settings and borders. They also exercise scratch eviction and spill ordering, maximum-size sparse and uniform samples, native Paint Bucket and Magic Wand, the HTTP Wand route, and Undo. Info.plist advances the build to 558. General dense 90-gigapixel turnaround, low-disk behavior under real storage pressure, full-size partial-opacity Bucket writeback, Clear in Bucket and live Photoshop pixel qualification remain open.

A separate maximum-size sparse save and reopen produced a 2,512-byte native archive and restored exact coverage and pixels. Cancelling a connected nonuniform background operation left the document unchanged. Magic Eraser also calls the shared matcher, while its downstream writeback remains outside this maximum-size qualification.

The first Debug run used an out-of-range translation in the new matrix. The corrected test uses a supported very small horizontal scale and still reaches the inverse coordinate guard. Its repair changed one test parameter. All 481 selected checks then passed in Debug and on both optimized architectures. The independent 240 masks and 18 bucket render buffers matched build 557 exactly. Both slices of the universal archive passed the offscreen workspace check.
