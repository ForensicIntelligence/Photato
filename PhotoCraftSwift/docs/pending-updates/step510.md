## 510 — Editable gradients in profile conversions

RGB profile conversion now keeps gradient fill layers and vector gradient fills and strokes editable. Stop positions, midpoints, opacity, interpolation, placement, masks and vector geometry remain intact. The operation uses the existing native Convert to Profile workspace and the same transaction exposed by the optional API. It makes one Undo entry. It does not add a menu item, shortcut, cursor, command identity or file-format version.

Imported vectors need extra care. A current cached image is converted with its definition and retains its bounds. A stale cache is discarded. Original opaque vector records and their source profile move to separate source provenance, so an old record cannot silently become the new paint definition. A conflicting provenance key rejects the transaction without replacing metadata. Pattern paints, non-RGB conversion and other unsupported stacks still require explicit flattening.

The first implementation failed four of 70 selected Debug methods. Those results and the pre-change regression are retained. The failures identified a strict range check rejecting ordinary white because ColorSync returned components slightly above one, an sRGB-only PSD import guard, and a test that incorrectly expected profile editing to require file-transfer permission. The repair explicitly clips finite gradient stop values to the existing bounded SDR domain. This includes the current RGB32 gradient controls; floating-point raster samples retain extended values. No epsilon or pixel-equality assertion was relaxed.

PSD and PSB can now retain non-sRGB RGB8/16 gradient fills whose stops are fixed RGB values. Profile-dependent tone layers, other color models and RGB32 descriptors keep their previous restrictions. Raster exports still composite the original image before converting its profile. Keeping editable gradient controls is a separate choice because nonlinear interpolation can change the rendered result. A new regression checks that distinction at all three depths through the published-output adapter.

The corrected focused run passed all 13 methods. Source04 then added an owned Photoshop-saved Display P3 fixture and a busy-state API test. All 106 selected Debug methods passed, including 14 new methods and the preceding reviewed-plan/runtime regressions. Every expected method ran once, with no skip or signal, on the same 7,748 source inputs. Tests include preview/Cancel, commit, Undo/Redo, all gradient methods and depths, cache provenance, invalid operations, authentication/stale/busy checks, both applicable API paths, native persistence and 300,000-by-300,000 sparse document geometry. The large geometry test does not qualify a fully dense maximum-size image.

Undo restored sRGB, Redo restored P3, and Save As/reopen preserved the editable document. Normal Quit passed. Its exact saved controls are now an import/re-export fixture.
