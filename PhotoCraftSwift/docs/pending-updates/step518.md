## 2026-11-09 — Editing video keyframes as a group

SP01 audit found clips, groups, split/trim, source and document frame rates, sparse drawing frames, audio/fades, transitions, work areas, onion skins, conversion, playback/export and individual property keys already implemented. The missing workflow selected here was multi-key selection and group editing, including an immutable clipboard. The full timeline/video scope remains open.

Checked Adobe’s public keyframe documentation and the installed Photoshop 2026 app. The current Timeline and keyframe context menus expose Delete, Copy, Paste, Select All, Deselect All, Linear Interpolation and Hold Interpolation. In an owned 160 × 120 RGB8 document, opacity keys at zero seconds/100% and one second/25% were copied together and pasted at two seconds. Photoshop showed 100% at the paste point and 25% at three seconds plus one frame, with four visible markers and the pasted pair selected. The owned PSD was saved privately, hashed and closed normally to Home. The Timeline panel height was restored. Screenshots and the observation receipt are retained. These observations do not establish multi-layer mapping, collision defaults or output-byte parity. No proprietary implementation was examined.

Added Core VideoKeyframeEditing.swift: explicit layer/key references, an immutable copy-on-write clipboard and atomic paste/delete/interpolation/move/duplicate edits. Paste keeps values, interpolation and relative times, replaces only matching property/time keys and selects the pasted result. Multi-layer mappings are explicit; one source layer can populate several targets. Group moves remove the selected source slots before collision checks. Locks, property compatibility and existing key/metadata limits apply. Key-count/per-layer/metadata admission happens before paste/duplicate allocation, preventing a full track replicated over many layers from creating millions of keys before final validation. VideoTimeline.swift delegates the new shared edit without changing archived key data.

Added native VideoKeyframeEditing.swift and AutomationKeyframeSelection.swift. EditorStore.swift retains view selection and separate native/API clipboard state. VideoKeyframeControls.swift adds checkable key lists, selection counts, matching context actions and explicit Move/Duplicate offsets. VideoTimelinePanel.swift exposes the Keyframes menu and selected-key state. The native clipboard is application-local across documents and leaves the operating-system clipboard alone. Source05 positions the inspector toward the window center using the leading attachment edge.

AutomationKeyframes.swift, AutomationVideo.swift and AutomationService.swift extend existing video.keyframe operations, strict parameter handling, schemas, observable state and capabilities. The HTTP clipboard is separate from the native clipboard and tied to the actual API session, share, transfer grant and document lifecycle. Copy/Paste require transfer permission; cross-document paste takes an explicitly shared source and its current revision, then rechecks source authorization and clipboard identity at commit. Selection and Copy add no content history; content operations share prepared native transactions and Undo. No Firefly endpoint, proprietary descriptor, main-menu shortcut or tool-modifier action was invented. Native 92, Actions 60 and 271 typed commands remain unchanged.
