## 2026-11-17 — Reuse recomposited tiles in the canvas

The layered Brush measurements from step 531 separate finding damage, brush stamping, recompositing the damage rectangle and installing the result. The existing installer walked every pixel of the completed patch through the normal setter, even when both buffers already held identical Float32 storage semantics. This created repeated tile lookups and alpha-proof invalidations on partly transparent canvases.

Surface.swift now offers an exact bounded replacement for matching Float32 grids. It checks that the source has finite sample storage and verifies visible alpha values against the existing setter's rules. Complete tiles retain their immutable sample storage. Unaligned rows replace only the visible part of the destination tile. Missing source tiles supply the real implicit sample. Cancellation and failed admission leave the destination unchanged, including its prior opacity proof. The normal compositor path in RenderSnapshot.swift still uses the prior sample setters when the source needs conversion or normalization. Paint controls, composition formulas, menu and shortcut behavior, archive structure and both application API contracts stay in their existing paths. The candidate bundle identifier remains in the Photato family and the build version advances to 532.

RasterScratchTests.swift checks exact mapped and retained sample bytes, full-tile sharing versus partial edge writes, HDR and signed zero, opacity proof invalidation, implicit clearing, rejection after an earlier tile has been staged, and cancellation. The existing regional render and history tests exercise the shared compositor.
