# 497 — Untagged Photoshop files and sandboxed copies

8 November 2026. Major stillneeded pass, I01. Current source: Source05.

Photato now opens the tested Photoshop RGB files created with “Don’t Color Manage,” retains their untagged status and preserves the neutral colour-management descriptor when saving PSD or PSB. Assigning a profile omits that stale unmanaged descriptor and writes the current ICC policy. Active OpenColorIO transforms, conflicting profiles and unrepresented metadata still reject explicitly.

Native testing exposed a separate Save a Copy defect. The save panel authorized the selected file, while our writer tried to create a temporary sibling beside it. The sandbox rejected that write. Routing the copy through AppKit’s Save To operation alone did not solve it: that path also passed the final destination into our writer. Both failed native attempts, their source snapshots, applications and kernel logs are retained.

The repaired path uses Foundation’s item replacement directory on the destination volume. The atomic writer holds the source and destination directory descriptors, validates their identities and publishes with `renameat`. It keeps the original size, cancellation, destination-change, visibility and synchronization guards. A failure after publication remains distinct from one that leaves the old file intact. Cleanup removes the replacement directory only if its identity is unchanged and it is empty. Sandbox entitlements are unchanged.
