## 2026-11-17 — Find changed tiles without sorting the canvas

Work continues on the layered 24 MP Brush case from step 530. A replay of the hosted AppKit test completed. The process sampler returned successfully but its report had no stack samples, so it supplied no function-level evidence. A standalone harness linked against the retained optimized build 530 core and imaging objects then timed the renderer directly. The first harness compile stopped because its timing function collided with Darwin's clock. The next attempt reached the renderer but omitted the ordinary brush settings that the desktop creates at mouse-down. The repaired harness used a standard 64 px brush and 240 deterministic samples on a 6000 × 4000 raster with two brightness/contrast adjustments. It compared complete packed and reduced preview bytes before reporting timings.

In the first successful run, median stroke composition was 6.67 ms and display packing was 0.98 ms per batch. Separating the renderer stages in a follow-up put median brush stamping at 1.12 ms, regional composition at 2.61 ms and copying the resulting rectangle at 0.67 ms. The rest of the render path includes identifying changed tiles, inspecting layer metadata, and constructing the result. The old direct tile comparison sorted both tile dictionaries' keys and visited every shared entry through the general union iterator.

RasterTileMap.swift now iterates direct dictionaries without sorting. It excludes tiles that demonstrably share immutable sample storage and includes new, removed and independently stored tiles for the existing bitwise comparisons. RasterTileStorage.swift provides the same storage-identity test already used by direct surface comparisons. Surface.swift checks cancellation before and after scanning. Persistent radix maps, mixed layouts and mapped-base admissions continue to use their existing paths. There is no change to brush smoothing, quantization, compositing, menu handling, archive fields or either HTTP contract. The optional API benefits only where it already uses shared surface comparison. The candidate bundle version is 531.

SurfaceValidationTests.swift verifies both directions of the candidate iterator and transparent signed-zero changes in the partial right/bottom tile. Existing regional renders, Undo/Redo, brush, mask, large-canvas, RGB32 storage and packed-preview tests cover the shared callers. [Photoshop painting performance](https://helpx.adobe.com/photoshop/desktop/apply-painting-techniques/brushes-presets/optimize-painting-and-cloning-using-brush-settings.html) documents the separate cost of brush settings and overlays. This work changes Photato's tile lookup before composition. Physical presentation and independent Photoshop byte comparisons remain open.

All 90 selected methods pass in Debug, optimized Apple Silicon and translated Intel. The universal archive and signature checks pass. The alternating optimized Brush runs found the 24 MP damage-scan p95 fell from 1.58 to 0.33 ms and the standalone batch-composition p95 from 9.06 to 6.85 ms. The three exact sample digests agree across all four runs. Hosted input-to-draw p95 on the same dimensions was 28.02 ms in build 530 and 23.55 ms in 531. Physical cadence remains open.
