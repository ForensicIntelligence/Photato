# Large native component documents

Checkpoint391 tests the sparse paths listed below on Apple Silicon and translated Intel. The full affected suite and colour-fidelity comparison retain failures; see [the qualification record](COMPONENT_DOCUMENT_ADMISSION_391.json).

Native component geometry admits300,000pixels per dimension (90billion logical pixels). Blank or sparse Gray, CMYK and Lab documents retain implicit component fills and small edit blocks. RGB retains its existing sparse canvas path; converting to retained RGB components uses the same logical geometry. This does not establish physical dense capacity or support for every operation at that extent.

The former8,388,608pixel constant remains NativeModeRaster.maximumPixels for dense legacy operations. The logical limit is maximumDocumentPixels. Document validation, history/recovery admission and the optional API use conservative owned component metadata/sample estimates; logical bytes no longer pretend to be heap allocations. Mapped sample bytes, presence-index bytes and virtual file extents are distinct. Their reference sums can count shared data repeatedly and do not measure RSS or physical disk allocation.

Native86 saves and checked raw component reads/writes retain exact sample words. Large retained components require native86 before HTTP download begins. Older native versions remain readable; explicit dense exports retain their old limit. The public Swift planes getter now throws, as planeBytes already does: callers add try and handle the unsupported dense-export error. A large document must use native86 or bounded raw sample access, rather than ask for a whole-plane Data allocation.

Channel visibility projects numerical values through implicit defaults and stored blocks. CMYK single-channel views still invert stored ink to view-gray. Hidden components use the same neutral words as the previous dense path. Numerical RGB interpretation preserves raw samples without a colour transform. Reconciliation updates changed implicit defaults, then restores unchanged native words over the component/cache block union. Crop and identity reframe stay sparse. These changes need exact comparison with the prior bounded algorithm as well as maximum-geometry workflow tests.

Unfinished component resampling, trim, expanded reframe with large overlap, individual component tools and channel blending retain explicit limits. PSD/PSB/TIFF component interchange and profile/printing paths retain separately qualified limits; Save availability directs large retained-component documents to Photato. These are temporary gaps in the full Photoshop goal, not completed features. No major package closes from the capacity increment alone.

The optional API keeps242commands and Actions46. Existing mode conversion, numerical channel pages, native file transfers, state and history share the desktop engine. Storage metadata exposes the logical/dense limits, native86requirement and owned/mapped accounting. Read offsets extend to the logical limit; transfers and other interface/job budgets remain independent. Stale/revoked/busy/invalid requests must retain their existing behavior. The Adobe-compatible interface keeps its published contract and separately reported coverage; no new proprietary Adobe endpoint or unsupported format option is invented.

The full acceptance still includes all Photoshop operations/profiles/settings/shortcuts, large PSD/PSB/TIFF interchange, complete current-suite success, supported physical Macs/macOS14+, current live UI, dense storage/metadata/recovery capacity and sustained60fps editing. The independent numeric cases and sparse maximum-geometry checks establish only the behavior they exercise.
