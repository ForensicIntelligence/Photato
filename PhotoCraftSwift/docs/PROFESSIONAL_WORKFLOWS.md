## Evidence and baseline

PhotoCraft's source is the migration baseline; Photoshop desktop workflows are the subsequent product benchmark. Pin the Photoshop version, OS, fonts, profiles, fixture licenses and expected outputs for each external comparison. Track behavior, editable document structure and visual fidelity separately. A flattened preview that looks correct does not prove an editable round trip.

At the user's direction, use Adobe's [All Photoshop Features catalogue](https://www.adobe.com/products/photoshop/features/all.html) as the primary discovery reference when a functionality delta is uncertain. Checked 2026-10-07. Follow the relevant official tutorial/help documentation and verify the behavior in the running Photoshop version before defining acceptance criteria. Map each applicable capability to the Rust baseline, Swift implementation and workflow tests; record unsupported or partial behavior explicitly. Catalogue entries are discovery evidence, not proof that either implementation has passed a workflow.

Evidence order: executable behavior and tests, current code, scorecard, then narrative roadmap. The source documents disagree in places:

- Pencil, Mixer Brush and Patch are marked done in [tools.toml](../../photocraft-main/scorecard/tools.toml), with source/test locations. Port them in Gate A; do not count them as new Photoshop features.
- `FILE-215-6` says projective Smart Objects are missing, but [SmartObject](../../photocraft-main/crates/doc/src/lib.rs) now has a projective matrix and [smart command tests](../../photocraft-main/crates/engine/src/smart_cmds/tests.rs) exercise Distort/PSD persistence. This is a Gate A behavior to verify.
- `TYPE-218-6` says optical kerning renders as metrics, but [optical.rs](../../photocraft-main/crates/text/src/optical.rs) implements optical spacing with Photoshop output comparisons. Port the implementation; audit remaining manual-kerning/UI/round-trip limitations separately.
- `FILE-216-5` reports missing atomic-save fault tests; [atomic/tests.rs](../../photocraft-main/crates/format/src/atomic/tests.rs) and the newer [bugs scorecard](../../photocraft-main/scorecard/bugs.toml) show they now exist. They belong in Gate A. Recent-files persistence has a similar stale UI-scorecard entry.

## Local and Private Cloud Compute AI architecture

### Choose by capability and execution location

| Provider | Intended use | Constraint / decision |
|---|---|---|
| Explicit Apple `SystemLanguageModel` | Refine prompts, describe command plans, organize text metadata | On-device text assistance on eligible macOS 26+; model output becomes validated typed commands/previews. It does not synthesize image pixels. Do not select a server model implicitly. |
| Image Playground on macOS 26 | Optional illustration/animation/sketch asset creation | Restrict styles and check real availability; live generation still needs a suitable test Mac. It is not the inpainting engine. |
| Image Playground on macOS 27+ | Optional illustration/animation/sketch asset creation through Private Cloud Compute | Enabled at the user’s request. Check actual framework availability and disclose cloud processing before generation. Apple manages connectivity and usage limits. This is not local inference or a masked inpainting backend. |
| Vision segmentation | Subject/object masks and refinement starting points | Evaluate the native foreground-instance API and appropriate OS revisions. Segmentation is not a guaranteed fine-hair/transparency matte; preserve editable/manual masks. |
| Swift + Core ML image pipelines | Fill/inpaint, expand/outpaint, reference-guided edits, image generation | Evaluate candidates using licensed weights and actual model capability. Apple's Core ML Stable Diffusion project is a runtime/reference candidate, not proof of production inpainting quality. No model selected or downloaded yet. |
| Local restoration models | Denoise, upscale, harmonization candidates | Separate model evaluations. Distinguish restorative processing from synthesized detail in the UI; never overwrite the source. |

First target image-AI qualification on Apple Silicon/macOS 26+. Editing remains macOS 14+. Core ML may support additional OS versions, but that needs its own verified support matrix. Provider packages must run through Swift and Apple frameworks with no Rust/Python service or browser runtime. Model conversion can be a development step outside the shipped app.

### Integration contract

1. `ImageEditRequest`: capability, immutable document revision, source layer IDs, working profile/depth, full-resolution edit mask, protected mask, source/context rectangle, prompt, optional references, seed if supported and output intent. Snapshot on dispatch; never let an asynchronous result apply silently to a different document/revision.
2. `LocalImageBackend`: explicit execution location, supported capabilities/resolutions, model/version/hash, hardware/memory requirements, progress and cancellation. A text-to-image model must not advertise inpainting merely because it accepts text. Unsupported capabilities remain unavailable.
3. A bounded background job actor prepares the crop/context, converts color for inference, tiles only when supported, handles memory pressure and returns image tiles plus provenance. Document mutations remain on the command path. Cancellation must discard late results even when the underlying accelerator cannot stop immediately.
4. A preview offers variants and an editable output mask. Commit creates a new result layer/group and one undo transaction; expand changes canvas bounds in the same transaction. Preserve original layers and full precision outside the edit. Store prompt, model/version, generation parameters, seed when exposed, references/provenance and selected variant in the native archive.
5. Save/reopen must preserve results even when the model is later unavailable. Regeneration is a new request and is not assumed bit-identical across hardware or OS/model updates. Export rendered pixels without implying another application can rerun the same model.
6. Optional model installation shows license, storage and hardware needs before a user-initiated download; verify hashes and provide removal. Local-backend inference is offline after provisioning, with no automatic cloud fallback. The separate Image Playground workflow may use Private Cloud Compute when explicitly invoked, with its processing location shown in the UI. Runtime availability is independent for text, segmentation and each image capability.

### Model evaluation and release criteria

Evaluate model/runtime license, weight redistribution and commercial use separately. Pin model hash, conversion settings, runtime version, test Mac, memory tier and OS. Benchmark cold/warm latency and peak memory with the editor open on 16/24/32+ GiB systems; determine actual supported tiers from results rather than inventing a minimum. Require understandable insufficient-memory behavior. Do not add a model simply because it converts successfully.

Use a fixed, licensed evaluation set covering portraits, products/logos, architecture, landscapes, fine hair, transparency, text, gradients and high-ISO detail. Run repeat trials and retain all outputs. Deterministic assertions cover exact protected pixels, alpha/coordinates/profile, valid dimensions, cancellation, undo and archive persistence. Human review covers seams, identity/reference preservation, anatomy, text damage, prompt adherence and useful resolution. Set per-workflow numeric thresholds before implementation; do not select only favorable generations or call probabilistic image quality 100% correct.

The first qualifying generative slice is masked object removal on a new layer. Follow with prompted replacement, canvas expansion, background generation, reference-guided variants, then harmonization/upscale if models meet their own gates. If no local model qualifies, keep that requirement open and report the quality/performance gap. The separately enabled Apple cloud service supplies optional asset generation; it does not satisfy the offline inpainting requirement.

## Test and delivery gates

Gate A: every applicable source feature has implementation, test evidence and native interaction; remaining source bugs and platform substitutions have explicit dispositions. No unaccounted pending command rows. Port existing fixtures and failure tests as part of each module. New professional requirements do not erase source-parity obligations.

Gate B: each workflow has component tests, an end-to-end native interaction, save/reopen/export evidence, and relevant independent oracles. Track states as planned → implemented → tested → externally verified; record blockers without treating them as passes. Pixel tolerances must be per-fixture, with exact equality for untouched data and named tolerances for color/render comparisons.

Run original `perf/budgets.toml` scenarios against the Swift build; distinguish p95 versus max metrics and previously unenforced targets. Examples include 25 ms layer-move updates, 20 ms opacity changes, 100 ms first 12 MP duplication and 200 ms worker cancellation. Declare benchmark hardware, document and warmup/repetition count. These targets are not currently passed by the Swift prototype. Add scratch/cache stress and multi-GB documents after removing the current development caps safely.

Release testing covers macOS 14 Intel/Apple Silicon for editing, macOS 26 Apple Silicon for optional system-local AI, macOS 27+ for Private Cloud Compute availability/presentation/cancellation and qualified local backends, low-memory states, unavailable models, offline operation, physical tablets, multiple displays/profiles, accessibility, recovery and signed/notarized installation. A build on one Mac is not runtime verification of the matrix.
