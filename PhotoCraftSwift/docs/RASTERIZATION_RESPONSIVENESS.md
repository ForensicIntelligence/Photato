# Rasterization responsiveness

Ordinary native Rasterize previously rendered and converted the selected layer synchronously on the main actor. The current path captures its layer ID and prepares the same rasterization command in the existing detached geometry worker, which already serves native PDF rasterization and the Photato API. The main actor validates the source/session and commits one Undo transaction. Existing busy, progress, cancellation and error handling apply.

Rendering and conversion mathematics are unchanged. The API remains `layer.rasterize` with `layerID`. Smart Object capability metadata describes asynchronous native preparation; no command, parameter, serialization version or Adobe descriptor is added. Native callers wait for the existing geometry task before reading committed content.

The owned pre-change Debug probe measured the actual old native call on 0.96MP and 24MP RGB8 Gradient Fill layers. Main-actor submission took about 9.56 seconds and 240.39 seconds, respectively, including synchronous commit. Profiling captured the main-thread rasterization, prepared edit and pixel-conversion stack. These are Debug samples, not optimized app timings or p95 estimates.

The current normal benchmark measures asynchronous native submission and geometry completion. It can also replay the exact pinned old synchronous expression inside the same current optimized process and check identical documents. That replay is labeled as a reference, not an old optimized binary measurement. Timings exclude initial and final preview publication; overlapping work and shared host load remain limitations.

Three new functional regressions cover 18 RGB8/16/32 gradient, solid fill, type, transformed shape, raster and Smart Object contexts. They compare legacy/native/API documents and saved bytes, Undo/Redo, cancellation, stale sessions and busy/locked/modal guards. Existing transformed-shape coverage now waits for the intentionally asynchronous native operation; PDF coverage retains its existing shared path.

The focused Debug run passed all three new methods, then an unchanged Shape API test terminated by signal 10. The exact case also crashes on the preserved checkpoint 419 Debug build. Both attempts are retained; this is not claimed fixed. Current optimized qualification includes that case and the recent native frame-drag and sky-rename additions. Both optimized architectures execute that case successfully. Each passes 193 of 195 cases, including all 18 new methods from 415–420; the two failures exactly match retained linked-preview alpha and master-palette cancellation failures. No Debug crash repair or full-suite pass is claimed.

A separate preserved optimized painting baseline retained all 240 samples per case. Its 24MP input/render/offscreen-draw p95 values were approximately 0.006ms, 12.73ms and 3.55ms. It does not establish physical 60fps or input-to-photon latency. Large tips/documents, other tools, modes, proofs, physical platforms and exact Photoshop behavior remain open. Complete Q03 and Photoshop parity are not claimed.

The optimized 24MP native submission takes 0.023ms on Apple Silicon and 0.046ms under translated Intel in these individual samples. Preparation completes in about 6.94s and 12.25s, respectively. The old synchronous expression replayed in the same processes takes 6.89s and 12.35s; it produces exactly equal documents. The improvement is main-actor availability, not a rendering-throughput claim. Both slices, macOS 14 minimum, ad-hoc sandbox signature, resources and extracted ZIP contents pass local packaging checks. The candidate is not launched or installed.
