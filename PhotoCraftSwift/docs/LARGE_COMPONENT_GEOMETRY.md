Native Gray, CMYK, Lab and retained RGB geometry samples authoritative numerical components through the same premultiplied interpolation kernel as raster geometry. It preserves the previous nearest/bilinear/bicubic and edge-clamping rules. It does not convert numerical ink values through RGB. A bounded write-back cache publishes immutable private component scratch; every plane shares the operation’s disk allowance. Failure, cancellation or I/O discards the candidate and leaves the source/history unchanged.

Nearest complete grid turns use implicit default words and move retained samples. Complete nearest mappings use a bounded sparse support list when eligible; dense inputs fall back to complete bounded evaluation. Other interpolation evaluates required output coordinates through direct numeric source reads. A large dense job can take substantial time; bounded storage is not a constant-time operation or a60fps claim. Alpha-zero interpolation can remain implicit because the existing premultiplied kernel returns transparent output.

Reframe chooses the larger uniform region as its implicit word, then writes required interior/background bands and retained overrides. A thin contrasting border can still require substantial physical storage with4096-sample blocks; its scratch budget and real I/O failures remain authoritative. Trim evaluates allocated component blocks and uniform gaps analytically, preserving the previous numerical comparison, alpha and edge rules. Empty output still rejects atomically.

Small local derived-cache edits retain their direct path. Larger native RGB and numerical/channel projections use bounded row-stripe occupancy and ordered RGB patches; there is no whole-canvas tile-key Set. Numerical channel replacement also writes bounded component scratch. Native layer transforms avoid an unused preliminary RGB resample. These paths do not establish complete profile/conversion/printing/interchange or dense recovery/metadata capacity.

Existing desktop Image Size, Fit Image, canvas turns, Trim/Reveal All and corresponding supported native/API/Actions/Batch commands continue to use their existing transaction/history path.
