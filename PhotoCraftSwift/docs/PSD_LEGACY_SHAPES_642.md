# Editable older Photoshop shapes and their pixel masks

19 November 2026 · Development preview 642

Some Photoshop files describe the silhouette of an editable solid-fill layer with `SoCo`, `vmsk` and live origination data. Photato now opens that combination as a shape layer. Photoshop's recorded bounding box and path already include the transformation. Photato checks that they agree, keeps the original path, and exposes independently editable shape geometry and user-mask pixels. Unchanged shapes keep the original shape records when saved to PSD or PSB. A geometry edit writes the current Photoshop shape records and retains the user's mask and its document coordinates. [Adobe file format specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)

The reference is an unmodified Photoshop-authored file distributed in the psd-tools corpus, with four solid rectangles and four separate pixel masks. The recorded mask densities are 64, 128, 191 and 255 on the file's 8-bit scale. The reference contains unequal X and Y scaling and positions outside the canvas. Native inspection also checks that this live shape path stays distinct from an ordinary solid fill with a vector clipping mask. [Pinned reference](https://github.com/psd-tools/psd-tools/blob/96eb134c17b2c65edf4c4151c0f00b802ada86c2/tests/psd_files/mask-density-layermask.psd)

The first independent export found an empty shape cache. The shared decoder had skipped the channels because the legacy record carries a solid-fill tag. The decoder now reads the cache as shape data. A second comparison measured two samples one level away from Photoshop where masked rectangles overlap. Rounding the aligned RGB8 shape's density-adjusted mask byte before compositing accounts for both. The same conversion runs for native and imported shapes with aligned, unfeathered RGB8 user masks.

Changes use the existing native Save paths and authenticated API downloads. `photoshopContainers.liveShapes.legacySolidFillRecords` describes the supported shape records. Legacy stroke variants, rotated or compound shapes, and documents that mix additional vector-mask processing with the retained shape contour remain open.

An independent parser compared both unchanged re-exports with the original file. In each export all 6,800 shape-layer RGBA bytes, 800 user-mask bytes, 4,720 shape-record bytes and 3,072 merged RGB samples matched. A width edit to 18.75 px also reopened in both formats with the selected mask's 216 samples and its placement intact. The reference file's nontrivial mask densities, overlapping shapes and off-canvas extents are included in those comparisons.
